# CLAUDE.md

## Purpose
Hyphlow ("Alchemic Logic Engine", package `com.ateliermycelia.hyphlow`, v0.7.x, open beta) is the
successor to the visual scripting system of [Fungus](https://github.com/snozbot/fungus/). It is
**not a drop-in replacement**: the core keeps Fungus's workflow (Flowchart → Blocks → Commands, Event
Handlers, Variables) but modernizes the architecture and editor. Dialogue, localization, etc. are meant to
ship as separate plugins, not in the core. Repo: https://github.com/Atelier-Mycelia/Hyphlow

It was split out of **Amanita**, which began as a holistic Fungus successor (Fungus Community Edition) and was
later broken into separate packages. Today "Amanita" means only the dialogue system split off from Fungus
(sibling repo `../Amanita`); Hyphlow is the visual-scripting core. Legacy names show up in the code: `[MovedFrom(sourceNamespace: "Fungus")]`, `[FormerlySerializedAs]` everywhere,
`LegacyFungusState`, `FungusPrioritySignals`, `Fungus*` priority commands, and `AtMycelia.Amanita`
usings. **Preserve serialization compatibility** (keep `FormerlySerializedAs` / `MovedFrom`; rename with
care) because users migrate existing Fungus/Amanita projects.

## Fungus → Hyphlow concept map
| Fungus | Hyphlow |
|---|---|
| `Flowchart` (MonoBehaviour) | `Flowchart` – same role, but delegates to `VariableManagerComponent`, `BlockExecutionManagerComponent`, `BlockManagerComponent` |
| `Block` | `Block : Node, IBlock` (`[RequireComponent(Flowchart)]`); has `AccessScope`, `BlockReference`, optional `EventHandler` |
| `Command` | `Command : MonoBehaviour, ICommand` – `[CommandInfo]` attribute for menu category; `Name` strips the "Command" suffix |
| `EventHandler` | `EventHandler` + `[EventHandlerInfo]`; many built-ins (GameStarted, KeyPressed, Collision, ButtonClicked, InputActionEventHandler…) |
| `Variable` / `VariableData` | Old types live in `Runtime/Variables/OldVariables` (legacy, auto-migrated). New model: `Muscariable` (`Variables/Muscariables`) + `*VarDatas` (`Variables/VariableDatas`) |
| `VariableSourceAsset` (renamed) | `VariableSet` ScriptableObject – shareable variables outside a Flowchart (`IncludeInRegistry`, `IncludeInSaves`, GUID `UniqueId`) |
| Static `FungusManager` | `HyphlowManager` singleton (`S`), created by `HyphlowRuntimeBootstrapper` from `Resources/Runtime/Prefabs/Hyphlow` and parented under Atelier Mycelia's shared root |
| Fungus tween/LeanTween | **HyphaTween** (separate package, bridged in `Runtime/HyphaTweenInt`) |
| Flowchart window (IMGUI) | UI Toolkit / modular `FlowchartWindow` (see below) |

## Unity / packages
- Unity 2022.3.30f1 minimum and Unity 6 (6000.0.67f1) both supported – avoid APIs unavailable in 2022.3. Project uses URP + Input System + TextMeshPro.
- Atelier Mycelia dependencies (Git UPM packages, see `Packages/manifest.json`): **CommonLib** (`AtMycelia.Common.*`; utilities, signals, `RootBootstrapper`), **HyphaTween**, **Myceliarium** (editor "control panel" framework). Sibling checkouts of these live in `E:\Github\_AtelierMycelia\`. Also `com.coplaydev.unity-mcp` (Unity MCP) is installed for editor automation.
- The shippable package is **only `Assets/Hyphlow`** (has `package.json`). Everything else in the repo is dev scaffolding.

## Repository layout
```
Assets/Hyphlow/                 UPM package root
  AtMycelia.Hyphlow.Core.asmdef   runtime asmdef (also contains #if UNITY_EDITOR bits)
  Runtime/                        Flowchart, Block, Command, EventHandler, Variables, Signals, System
  Editor/                         AtMycelia.Hyphlow.Editor.asmdef (Editor-only)
  Resources/{Editor,Runtime}      UXML/USS, icons, manager prefab, HyphlowStandard_IA.inputactions
Assets/Tests/                   HyphlowTests.asmdef (Editor), PlayMode/ (AmanitaPlayModeTests.asmdef), Editor/ (HyphlowEditorTests.asmdef)
Assets/HyphlowSamples/          Sample scenes (Conditions, HyphaTween, Playground, PreTitleScreen)
Assets/_DevOnlyTools/           Internal migration/cleanup helpers – not shipped
Assets/Scenes, Settings, ...    Host project stuff
```
Root `*.csproj` / `.sln*` / `Library` / `Temp` / `Logs` / `obj` are generated by Unity – never hand-edit.

### Runtime (`Assets/Hyphlow/Runtime`, namespace `AtMycelia.Hyphlow`)
- `Flowchart.cs`, `Node.cs`, `Blocks/` – `Block`, `BlockManager`, `BlockExecutionManager` (+ `*Component` MonoBehaviour wrappers), `BlockReference`, `IBlock`/`IBlockSource`/`IBlockLogicHandler`.
- `Commands/` – base `Command`/`ICommand`/`CommandAdapter`, then built-ins by category folder: Animation, Audio, Flow (If/Else/While/Call/Jump/Label/Wait/LoadScene…), Input, Math, Physics, Priority, Property, Scene, Scripting, Sprite, UI, Variable, Vector3. `HyphaTweenInt/Commands` has tween-based ones.
- `EventHandlers/` – base + MonoBehaviour/Physics/UI subfolders.
- `Variables/` – `VariableManager`, `VariableSet`, `VariablePointer`, `AccessScope`, factories, Muscariables/VarDatas, plus `OldVariables` legacy.
- `Signals/` – static `Action`-based event buses (`BlockSignals`, `CommandSignals`, `FlowchartSignals`, `FlowchartWindowSignals`, `VariableSignals`). Prefer signals over direct coupling; "Editor-Only Signals" regions exist.
- `System/` – `FlowchartRegistry`, `FlowchartGlobalDefaults`/`FlowchartEditorQol` (ScriptableObject settings), `SceneLoader`, `HyphlowConstants`.
- `Utils/` – `ConditionExpression`, string-variable substitution (`{$var}`), `VariableRegistry`, attributes.

### Editor (`Assets/Hyphlow/Editor`, namespaces `AtMycelia.Hyphlow.EditorExt` etc.)
- `FlowchartWindow/` – the node-graph editor, split into small collaborators wired through `Contracts/` (`IFlowchartHost`, `IFcWindowComponent`, `IFlowchartWindowModule`, `IModuleDispatcher`): `Core/FlowchartWindow.cs` (host), `Coordinators/` (Selection, Clipboard, PlayMode, Refresh, Teardown), `Dispatchers/` (route input to modules), `State/` (document, selection, interaction), `Rendering/`, `Ui/` (UI Toolkit builders, variables panel, context menus), `Clipboard/`, `UguiEventHandlers/` (zoom, box select, delete).
- `Visuals/` – custom inspectors/editors (`BlockEditor`, `FlowchartEditor`, `CommandEditor`, `VariableSetInspector`…), property drawers, popups (command/event/variable selectors), variable row management (`Variables/RowVisualHandlers`, `VRowManagement`).
- `Infrastructure/` – bootstrap on domain reload, default-asset maintenance, `HyphlowEditorPreferences`, legacy variable auto-migration (`LegacyVariableAutoMigrator`, `VariableSetMigrationRunner`).
- `Myceliarium/` – Hyphlow's tabs in the Myceliarium control panel (global defaults, editor QoL).
- `ToolsMenuItems/` – Tools menu entries; `Extensions/`, `Utils/`, `UiCommon/` helpers; `UxmlAutoFixerPostprocessor`.
- UI is UI Toolkit: UXML/USS in `Resources/Editor/{Uxml,Stylesheets}`, with IMGUI retained where needed (`SafeIMGUI`, `Visuals/IMGUI`).

## Building / testing
- No CLI build; open in Unity (2022.3.30f1 or 6000.0.67f1) and compile there. Run tests via Test Runner (EditMode: `HyphlowTests` / `HyphlowEditorTests`; PlayMode: `Assets/Tests/PlayMode`). With Unity MCP available, use the `unity-mcp-skill`.
- Any new `.cs` / folder needs its `.meta` file committed (Unity generates them – don't delete or hand-write GUIDs).
- Editor-only code goes in the Editor asmdef; the Core asmdef must not reference `UnityEditor` outside `#if UNITY_EDITOR`.

## Code conventions (from CONTRIBUTING.md)
- Classes/methods/properties `UpperPascalCase`; private/protected fields `_camelCase`; public fields, args, locals `camelCase`. Acronyms only capitalize the first letter (`HttpFmodClient`).
- Lifecycle hooks, serialized fields, and callbacks are `protected`, not `private`. Class order: serialized fields, then lifecycle methods in execution order.
- Helper methods go directly after the first method that calls them (top-down reading). Use local functions for small helpers.
- Comments explain *why*, not *what*; no Captain-Obvious comments. XML docs on public APIs; name params well instead of documenting them.
- Folder reorganizations: never create a folder for a single script; only create a new folder when ≥5 scripts (the new one + 4 others) belong in it.
- Existing style: 4-space indent in most files, Allman braces, `#if UNITY_EDITOR` for editor-only members in runtime types.

## Working notes
- When porting a Fungus feature, check the Fungus source first (https://github.com/snozbot/fungus/), then check `../AmanitaLegacyCollection` (Amanita parts split off as redundant or likely to be replaced by future systems; most have since been reintegrated into Hyphlow to avoid depending on those systems, so look in Hyphlow first and only treat what remains there as a reference); dialogue features belong in Amanita, not here. Keep the Fungus command/event name so users can find it.
- AI use is disclosed in the README (debugging, small repetitive tasks, architecture improvements).
